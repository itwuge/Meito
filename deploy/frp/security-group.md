# 安全组端口清单（sg-2vchr9d5anwtxrk1y1vi）

> 节点：阿里云 ECS，成都可用区 B，公网 IP `47.109.32.249`，内网 `172.31.251.216`
> 安全组：`sg-2vchr9d5anwtxrk1y1vi`
> frp 版本：`v0.71.1`（规则以该版本为准）

## 结论先行

- **入方向必需规则只有一条：TCP 7000，来源 `0.0.0.0/0`。**
- **本版本没有服务端 UDP 打洞端口，不要预先开放任何 UDP 入方向端口。**
  依据：v0.71.1 的 `ServerConfig` 没有 UDP 协调端口字段；`server/service.go` 只监听
  `bindPort`（TCP），KCP/QUIC 只有在显式配置 `kcpBindPort`/`quicBindPort` 时才监听 UDP。
  XTCP 的 UDP 套接字在 **frpc 两端**，STUN 由客户端访问外部 STUN 服务，不经过本节点。
  > 该结论来自源码与配置参考；**真机 `ss -lunp` 尚未执行，标记「未验证」**。
- 仪表盘、HTTP/HTTPS、TCP/UDP 转发、KCP/QUIC、Prometheus 一律不开放。
- SSH 22 不建议对 `0.0.0.0/0` 开放；只允许管理员固定出口 IP。

### 旧版本对照（仅用于防止误配）

如果实际部署的 frp 是 **v0.52 之前的 INI 配置版本**，XTCP 可能要求 frps 配置
`bind_udp_port` 并开放一个 UDP 端口；那种情况下才需要按该版本文档开放**单一 UDP 端口**。
本包锁定 v0.71.1，**不适用**，不要提前开放。

判断方式：以 `frps -v` 和实际配置字段为准；不要凭经验假设端口号。


## 入方向规则

| 优先级建议 | 协议 | 端口 | 来源 | 用途 | 是否必需 | 说明 |
|---|---|---|---|---|---|---|
| 1 | TCP | 7000 | `0.0.0.0/0` | frpc 登录、心跳、XTCP 打洞协调 | **必需** | 唯一对外服务端口。TLS + token 鉴权；安全组无法可靠按 GitHub 托管 runner 出口 IP 收窄，见下文 |
| 2 | TCP | 22 | 管理员固定公网 IP `/32` | SSH 运维 | 可选 | 不要 `0.0.0.0/0`。优先用阿里云控制台 VNC，减少暴露面 |
| — | 任意 | 其他 | 任意 | — | **禁止** | 包括但不限于 80/443/7500/7001/7002/6000-6999/9090 |

### 为什么 7000 只能开到 `0.0.0.0/0`

- 连接来源有两类：
  1. GitHub Actions 托管 runner 上的 frpc；
  2. 用户本地机器上的 frpc（visitor 或本地 CLI）。
- GitHub 托管 runner 的出口 IP 不是稳定单 IP；官方只提供会变化的 IP 段清单，不能作为长期白名单。
  **「能否固定到 GitHub 官方 actions IP 段」未验证，不作为默认方案。**
- 用户本地出口 IP 可能是动态的，强制白名单会导致会话随机失败。
- 因此默认全局开放 7000，用 token + TLS + 服务端监听面/流量验证来控制风险。
- 如果以后使用**自托管 runner**且出口 IP 固定，或用户有固定办公 IP，可把来源收窄为对应 `/32`；
  这属于可选加固，不是当前必需项。

## 明确禁止对外开放的端口

| 端口 | 协议 | 对应能力 | 为什么禁止 |
|---|---|---|---|
| 7500 | TCP | frps 仪表盘 / 管理 API | 可查询/管理代理与会话；配置中已关闭（`webServer` 未配置，端口 0）。任何情况下不得对公网开放 |
| 80 / 443 | TCP | vhost HTTP / HTTPS 代理 | 会直接承载应用层流量，违反「只打洞」约束；配置中未启用 |
| 7001（或任意自定义值） | TCP | tcpmux HTTP CONNECT | 复用控制端口承载 HTTP 数据，禁止 |
| 7001 / 7002（或自定义值） | UDP | KCP / QUIC 控制通道 | 本场景不需要额外 UDP 监听；开启只会扩大攻击面 |
| 6000-6999 | TCP/UDP | 典型 TCP/UDP 远程转发端口 | 一旦有客户端注册 tcp/udp 代理，这些端口就会承载会话数据；配置中不注册任何 tcp/udp 代理，安全组也不放行 |
| 9090 / 7400 | TCP | Prometheus / 其他监控 | 未启用；监控数据可能暴露代理信息 |
| 任意其他端口 | 任意 | — | 默认拒绝。必须确认没有遗留的 `0.0.0.0/0` 全端口放行规则 |

> 安全组的默认行为是「未匹配任何允许规则即拒绝」。请重点检查是否存在历史遗留的
> `全部流量 / 全部端口 / 0.0.0.0/0 允许` 规则，它会覆盖上面的最小化结论。

## 出方向

默认「允许所有」可以接受，但建议按需收窄：

| 协议 | 端口 | 目的 | 说明 |
|---|---|---|---|
| UDP | 123 | NTP 对时 | 时间偏差会影响 token 时间戳校验与日志排序 |
| UDP/TCP | 53 | DNS | 仅系统解析需要；frps 本身用 IP 连接，不依赖域名 |
| TCP | 443 | 系统安全更新 / 手动下载 frp | 若采用 ESM 或定期升级，需要放行 |
| 其他 | — | — | 可按「默认拒绝出方向」进一步收窄，但不要影响 apt/NTP |

frps 不需要主动访问互联网；不要给它配置 HTTP 代理或出站转发规则。

## 阿里云控制台操作步骤

1. 登录阿里云控制台 → ECS → 实例 → 安全组 `sg-2vchr9d5anwtxrk1y1vi`。
2. 入方向 → 手动添加：
   - 协议：TCP
   - 端口范围：`7000/7000`
   - 授权对象：`0.0.0.0/0`
   - 优先级：1
   - 描述：`meito frps control/xtcp signaling only`
3. 如确需 SSH：新增 TCP `22/22`，授权对象填管理员固定 IP `/32`，不要用 `0.0.0.0/0`。
4. 检查并删除任何允许全部端口或全部协议的宽规则。
5. 不要把域名 `wuge.fun` 的 80/443 规则加到本安全组；本节点不提供 HTTP 服务。

## 验证方法（详见 verification.md）

在**另一台非本机**上执行：

```bash
nc -vz 47.109.32.249 7000          # 预期 succeeded
nc -vz -w 3 47.109.32.249 7500     # 预期超时/拒绝
nc -vz -w 3 47.109.32.249 80       # 预期超时/拒绝
nc -vz -w 3 47.109.32.249 443      # 预期超时/拒绝
```

```bash
# 如果安装了 nmap
nmap -Pn -p 22,80,443,7000,7001,7500 47.109.32.249
```

预期：只有 7000 为 `open`（若开了 SSH 且来源匹配，22 为 `open`）；
其余为 `closed` 或 `filtered`。`filtered` 说明被安全组丢弃，属于正常。

在服务器本机执行：

```bash
sudo ss -lntp | grep -E 'frps|:7000'
sudo ss -lunp | grep frps || echo 'OK: no frps UDP listener'
```

预期：只有 `0.0.0.0:7000`（或 `[::]:7000`）由 frps 监听；没有 frps 的 UDP socket。
如果 `ss -lunp` 出现 frps 的 UDP 端口，说明误配了 KCP/QUIC 或版本行为与预期不符，
必须停下来排查，不能直接放行。
